## How It Works

1. Tell us what you need.
2. We review the request.
3. We confirm scope and price.
4. We perform the service.
5. We document important results and next steps.

## Request Service

The first production form should collect only:

- Name
- Email
- Phone (optional)
- Customer type
- Service division
- Service requested
- Remote/on-site preference
- Short description
- Preferred contact time
- Optional attachment only when necessary

The form should not request passwords, authentication codes, full payment-card data, SSNs, identity documents, or other unnecessary sensitive information.

## Future platform

The same repository can later add:

- customer accounts
- service tickets
- quotes
- invoices
- payments
- service history
- documents
- recurring support plans

Supabase can provide the database/authentication/storage layer, while Vercel can host the application.

## Existing cellular foundation

Existing cellular/eSIM functionality remains isolated behind product/provider gates. It should not dominate the public technology-services website until the cellular product is independently validated and intentionally launched.
