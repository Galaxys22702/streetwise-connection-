Streetwise commitment

Security First

Security should shape how Streetwise accounts, activations and provider connections work from the beginning.

The commitment

Streetwise is being designed so security is part of the product architecture and operating process, not a marketing add-on. The goal is to reduce unnecessary access, protect sensitive credentials, make high-risk account changes deliberate, detect problems where technically possible and give customers a clear recovery path when something goes wrong.

Account access

Customer account access should require appropriate authentication and should not expose sensitive information unnecessarily. Recovery procedures must balance helping the legitimate customer regain access with preventing an attacker from using support as a shortcut around account protections.

SIM-swap and eSIM-change protection

Changing a SIM or eSIM can transfer control of a mobile line to another device. Streetwise intends to apply stronger verification to these changes than to ordinary profile updates, using the best controls supported by the selected wholesale provider and implemented Streetwise system. Exact protections will be published only after they are available and tested.

Number-port protection

If Streetwise launches number portability, port-out requests should use provider-supported identity, account and transfer controls designed to reduce unauthorised movement of a customer's number. Streetwise will not advertise specific port-lock or transfer-PIN capabilities until the selected provider actually supports them for Streetwise customers.

Provider credentials and API access

Wholesale-provider API keys, tokens and other service credentials are not intended to be placed in public source code, browser JavaScript or customer-facing pages. Production credentials should be stored and used through controlled server-side environments with access limited to the systems and people that actually require them.

Payments

Streetwise's payment architecture is intended to minimise direct handling of sensitive payment-card information by using an approved payment provider and server-side controls. Live billing remains disabled until the production payment configuration and launch gates are ready.

Customer data

Streetwise intends to collect and retain only the customer and operational data reasonably required to provide, support, secure and account for the service, subject to legal, regulatory and provider obligations. Access to sensitive operational data should be restricted rather than broadly available across the system.

Logging and monitoring

Security-relevant events such as authentication activity, provisioning changes, provider events and important administrative actions should be logged at an appropriate level so problems can be investigated. Logs should not deliberately contain passwords, full payment credentials or provider secrets.

Fail-closed launch controls

Streetwise currently keeps live billing and live cellular activation disabled. Provider integrations that have not received commercial approval are not treated as production-ready merely because code exists. This reduces the risk of exposing customers to an unapproved or partially configured service path.

Software and dependency security

The Streetwise codebase is maintained with verification checks and dependency updates. Security work also includes reviewing how new provider integrations affect authentication, data handling, webhooks, billing and customer support before those integrations become live.

Incident response and recovery

If Streetwise detects or is informed of a security problem, the intended response is to contain the affected function where possible, preserve useful evidence, determine what happened, restore safe service and communicate material customer impact when required. The exact operational process will be finalised before commercial launch.

What customers still control

Customers remain responsible for protecting their device passcode, email account, authentication factors and verification codes. Streetwise support should not ask customers to post passwords, PINs or one-time verification codes publicly.

What “Security First” does not promise

No mobile provider can honestly guarantee that fraud, phishing, account takeover, SIM-swap attempts, software vulnerabilities or network attacks will never occur. Streetwise's commitment is to design for prevention, limited access, controlled changes, detection and recovery while being explicit about the protections that are actually available.

Current status

Several security capabilities remain dependent on the final wholesale provider and production implementation. Streetwise will not present planned protections as live until they are contractually supported, implemented and tested.
