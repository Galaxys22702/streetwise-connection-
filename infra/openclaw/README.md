# Jarvis OpenClaw model compatibility

The Railway image builds the pinned upstream template with this directory as its build context. Setup uses OpenClaw's provider defaults when Model is blank. Full model IDs, provider aliases, custom endpoints and gateway routes are passed to OpenClaw without comparing them to the setup group's name. A rejected model change is reported as setup failure.

Status refresh preserves the chosen provider and authentication method. Explicitly changing either clears the previous draft key and model so they are not reused with a different provider. Persisted authentication and conversations are unchanged.

Every provider still needs its own supported authentication, model entitlement, network access and, for a self-hosted provider, a reachable endpoint. Interactive device-code methods retain upstream's Railway-console wizard requirement. This change does not make every remote model available or verify paid provider access.

The opt-in `JARVIS_APPLY_LOW_MEMORY_POLICY=1` policy now disables optional non-provider plugins only. Normal restarts preserve plugin settings.

For an existing installation where the old memory policy blocked Anthropic, Ollama or xAI, temporarily set `JARVIS_RESTORE_MODEL_PROVIDERS=1` in Railway and redeploy this image. Restoration requires the original `openclaw.json.jarvis-before-plugin-optimization.bak`; it removes only those three provider denials absent from that backup and saves the current configuration separately before changing it. Denials present in the original backup, other plugin settings, credentials and conversations remain unchanged. Remove the flag after restoration so future explicit provider denials are respected. Missing or invalid backups cause a safe skip; review those installations manually in OpenClaw.

Deploy the updated commit on the branch configured for the OpenClaw service. A successful Streetwise deployment does not verify the separate OpenClaw image. After deployment, select a configured provider/model and send a short message from the live UI. Code tests and a successful image build do not prove provider credentials or model availability.

## Gemini key updates in Railway

On startup, a non-empty GEMINI_API_KEY can be bound through OpenClaw’s native Google API-key environment SecretRef. The key stays in Railway; configuration stores only its variable name. The former OPENCLAW_LIVE_GOOGLE_KEY export had no production override effect. This repair uses a dedicated env-secret provider allowlisted to GEMINI_API_KEY, preserves the Google model catalog and all saved auth profiles/chats, and backs up the original configuration once with private permissions. Future key rotations need a Railway restart/redeploy, not another key copy.

Explicit Google credential bindings, OAuth choices, credential headers/request authentication, custom endpoints, noncanonical provider names, custom replacement catalogs and conflicting secret-provider settings are preserved rather than overwritten. JARVIS_USE_RAILWAY_GEMINI=0 disables the startup repair. Non-JSON or included configuration is preserved and needs manual review. Explicitly pinned session profiles can still require selecting the native provider binding in OpenClaw. Check the startup reason if the repair is skipped. Code validation does not establish that the provider key is valid or that the live service has deployed this image.

## Guarded OpenRouter recovery

`JARVIS_RECOVERY_MODEL` is an explicit startup opt-in for the old Inkling default. It accepts only `openrouter/<provider>/<model>:free` or `openrouter/openrouter/free`, and changes only the exact `openrouter/thinkingmachines/inkling:free` primary. It requires a private, successful, exact backup at `openclaw.json.pre-jarvis-recovery` before changing the file. Included configs, restrictive model allowlists, replacement catalogs, conflicting backups and other defaults are preserved. `OPENCLAW_CONFIG_PATH` is honored. Logs contain a reason code, never configuration contents.

This is a default-model migration, not automatic timeout detection. Session overrides and existing fallbacks remain unchanged. Verify the replacement in the live model picker, remove the flag after recovery, and select the new default for an existing session if it has an override. Neither a passing health check nor HTTP 200 from the provider proves a completed answer. Free-model availability and limits vary.

### Paid Auto default recovery

A free model selected for one conversation does not replace the configured default used by setup probes, heartbeats or other sessions. The November 2 runtime logs showed `openrouter/openrouter/auto` as the gateway default and billing failures from that route. OpenRouter’s own setup writes that same id into `agents.defaults.model.primary` and as the only `agents.defaults.models` allowlist entry, so a migration that refuses an unlisted destination never leaves the paid route.

This image repairs that exact id on startup. The destination is `openrouter/openrouter/free` unless `JARVIS_RECOVERY_MODEL` names another accepted free model. The repair rewrites only exact Auto references in the default, fallbacks, utility/image slots, agent entries and the allowlist key. It also recognizes the same known Auto aliases in `model` and `modelOverride`, including split OpenRouter provider fields, and rewrites exact `systemPromptReport.model` pins in each agent `sessions/sessions.json`. Credentials, plugin settings, conversation text and every other model stay as they are. Each changed file gets a private exact `*.pre-jarvis-recovery` backup first; a conflicting or unreadable backup leaves that file untouched.

`JARVIS_RECOVER_PAID_AUTO=0` keeps Auto. Empty, `true` or any other value also leaves it in place. Included configs, replacement catalogs and allowlists that do not already contain Auto or the destination are not modified. Check startup logs for `Model recovery: recovered.` or `sessions_recovered.`; `preserved_model` means no Auto route remained. Node pairing and command approval stay manual. Operator browser pairing on this Railway image is covered under “Operator pairing on Railway.” To roll back, stop the gateway and restore the private backups before restarting.

## Foreground free-chat profile

Set `JARVIS_FREE_CHAT_PROFILE=1` on the **JARVIS-OpenClaw service only** to apply the guarded startup profile after model recovery. It accepts the existing free-router or exact Inkling default with free-only fallbacks. It selects the free router, removes Inkling and duplicate-primary fallbacks, uses `thinkingDefault: minimal`, caps an unlimited/long turn deadline at 120 seconds, and stops default periodic heartbeat calls with `heartbeat.every: "0m"`. An already tighter positive deadline stays tighter. Other configured free fallbacks and existing free-model metadata are preserved. This limits unproductive retries; it is not a measured speed guarantee.

November 3 logs show that disabling reasoning causes the free endpoint to reject a request. Minimal reasoning keeps that endpoint compatible; use `/think medium` in chat for a more deliberate answer when needed. Do not enable a provider's paid priority tier to chase speed. The profile leaves `fastModeDefault`, providers, plugins, memory, tools, approval rules, credentials, custom agent overrides and scheduled cron jobs unchanged. Heartbeats explicitly configured on individual agents and memory-plugin background tasks require separate quota review.

Existing sessions can override a corrected default. For known free-router/Inkling sessions, this profile recognizes both full IDs and OpenClaw's `providerOverride`/`modelOverride` and `modelProvider`/`model` split pairs. It clears their explicit model selection so the configured default and its fallbacks can apply, and sets their thinking level to minimal. With paid-Auto recovery enabled (the image default), known Auto aliases also lose their explicit selection and inherit the verified free default. `JARVIS_RECOVER_PAID_AUTO=0` preserves those Auto selections. The same rules apply to canonical SQLite rows in `agents/<id>/agent/openclaw-agent.sqlite` (`session_nodes.entry_json`) and to an absolute `agentDir` recorded on an agent that does not set its own model. Transcript tables, conversation text, historical `systemPromptReport` data, locked selections, pending fallback rollbacks, and external ACP sessions are not rewritten. A private `openclaw-agent.sqlite.pre-jarvis-free-chat-v1` snapshot is required before the first SQLite change; it is created with mode 0600 before any data is written. If another SQLite change would be needed while that snapshot already exists, the migration skips it rather than overwriting or reusing a potentially stale backup. `sqliteApplied` and `sqliteSkipped` are separate from the legacy JSON store counts. A database without `session_nodes.entry_json` is skipped rather than imported.

`JARVIS_RELEASE_SQLITE_PINS=1` releases those SQLite pins without retuning heartbeat, timeout, or thinking defaults. It still refuses the change unless the saved default is already the free router or exact Inkling route and no per-agent model would become exposed. When both this flag and `JARVIS_FREE_CHAT_PROFILE` are disabled, SQLite selections stay untouched. `/model default -s` and `/think default` remain the live-session commands when this startup release is not enabled.

Every modified file requires its own exact private `*.pre-jarvis-free-chat-v1` backup, separate from older model-recovery backups. Config backup failure prevents session changes; per-session failures appear in `sessionsSkipped`. Included configuration, replacement catalogs, restrictive allowlists, custom per-agent model overrides, symlinks and conflicting backups cause a safe skip. Requiring agents to inherit the default prevents clearing a free session pin from exposing a paid agent override. Sessions with a pending model rollback are preserved. The profile runs before the gateway starts. Remove/disable the flag after the one-time migration if future choices should not be re-evaluated. Disabling it does not restore old settings. To roll back, disable it, stop the gateway, restore the relevant private backups, and restart.

After a build, verify `Free chat profile: {"reason":"applied",...}` (or `unchanged`) with zero skipped stores, the gateway's free model/minimal-reasoning startup line, and a completed response from an approved browser. HTTP 200 from OpenRouter only proves the stream opened; a completed assistant message and elapsed time are required. Neither unit tests nor Railway health prove chat completion, live session contents, or fallback success. Free models have shared capacity and rate limits; changing models does not reset an account's daily quota.

### Canonical certification recovery

OpenClaw 2026.9.9 clears `session_nodes.entry_valid` through a trigger when `entry_json` changes. Its native session writer restores certification after a validated rewrite. This migration requires an already certified row with matching JSON/column identity and restores `entry_valid=1` in the same transaction after changing model-only metadata.

The first November 6 SQLite rollout omitted that certification step and caused gateway startup admission to fail. Startup now repairs only an exact rewrite attributable to its existing private snapshot: the snapshot row must have been certified, all other promoted columns must still match, identity must match, and current JSON must equal the known planned model-only transformation. Unrelated invalid or subsequently edited rows are left alone. This narrow repair runs even when both migration flags are off, changes certification only, and reports `sqliteCertified`/`certificationSkipped`. It does not run a general `doctor --fix` or restore/replace a database.

## Operator pairing on Railway

The public dashboard is HTTPS in the browser and loopback inside the container. Gateway auth can succeed while the browser stays on `pairing required`, and there is no host shell in which to run `openclaw devices approve`. `JARVIS_APPROVE_LOCAL_OPERATOR=1` (the image default) waits until `/setup/healthz` reports `gatewayReachable`, then approves at most three pending requests per pass, and only when the requested roles are exactly `operator`. Node-role requests, mixed roles, missing ids, and anything that is not a UUID stay pending. Set the variable to `0` to keep every approval manual. The log records an eight-character request prefix, not the device record. Command approval and node pairing stay manual.

`JARVIS_STATUS_PROBE=1` sends one gateway agent turn after the gateway is reachable, on session `jarvis-status-probe`, pinned to `openrouter/openrouter/free` with minimal thinking: “JARVIS, report your operational status and respond with JARVIS ONLINE.” It does not use `--local`, because a local run refuses the state directory while the gateway holds it. The log records the exit code and whether the reply contains that sentence, the free router, or paid Auto. Secrets matching `sk-…` are redacted. Leave the variable unset, or set it back to `0`, after the check. It is one free-router request per process start, not a heartbeat.
